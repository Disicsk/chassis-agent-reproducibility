# 底盘设计决策 Skill

将工程师的要求形成可复算、可审核的底盘初步方案。先保证约束满足，再按工程师明确的偏好比较方案。当前计算适配左右独立双HST与直行—转向双功率流两类履带式模型；其他车型先判断模型适用性。

## 形成决策依据

- 将给定事实、待确认输入、可选元件、硬约束、选型偏好分别整理。优先级和裕量门槛也是用户条件，缺失时应询问，不能自行加上“排量越小越好”或“必须保留旧方案”。
- 补问集中到会影响当前计算或方案取舍的字段。已确认的数值写入结构化输入；构型改变时先补齐相应模型参数。
- 从当前允许目录获得候选，调用共享工程工具形成当前输入下的约束证据。某个候选失败只代表该候选；无解结论需要覆盖当前允许范围。

## 在可行方案之间作选择

读取 [决策指标与工具接口](references/decision-contract.md)。使用同一套公开优先级比较候选，分别说明约束满足和选型理由。

- 有明确“优先保留原规格”的要求时，先检查原规格。它满足当前约束、裕量门槛，且本次仅按规格位置变更数排序时，0处变更已是可证下界，可以停止搜索。
- 若优先级还包含裕量或规格指数，先满足前一项，再比较后续项。只有局部检查时不得声称全目录最优；没有足够下界证明就扩大检查范围。
- 新方案多目标取舍采用工程师确认的顺序，允许并列。没有报价、结构质量或效率曲线时，不把排量指标当成价格、整机质量或能耗。
- 工具能批量完成的校验与比较可一次委托。模型负责理解条件和决定范围，数值由工具返回；不要用额外文字推演代替已提供的计算。

## 接续需求修改

识别变更作用于物理输入、允许目录还是选型偏好。每次仍校验当前输入和目录；交给共享工具按完整依赖哈希判定数值证据能否复用，不凭记忆宣布旧计算有效。

只改变偏好时，可复用相同物理输入的计算，但必须重新排序；只改变某个工况时，复核该工况并保留其他工况仍有效的证据；质量、速比、效率或限值改变时，重新核算受影响的全部工况。原候选失效后，依据实际失败约束扩大候选检查，而非直接放宽用户条件。

## 提交

提交当前输入、候选规格、适用工况、各硬约束结论、偏好比较、检查范围和仍未覆盖的工程内容；有历史方案时给出保留或更换理由。

默认提交状态为“待工程师审核”。试验中的脚本确认只能记为脚本确认。未经实际审核，不写“工程师已批准”。无解时分别报告原候选证据与全集证据，任何条件放宽建议都标明仍需复算。

本Skill不包含正式题、参数答案或隐藏评分信息。它是待检验的流程知识，不能保证优于通用Agent或固定程序。
